# Status Note: D-refactor Round 1 (D1+D2 cleanup)

## Scope reviewed

`app/main.py`, `app/config.py`, `app/database.py`,
`app/domains/finance/models.py`, `app/domains/finance/schemas.py` —
everything merged to `main` so far (D1 + D2).

## Finding

One genuine duplication: `CreditAccount` and `FinancialTransaction`
both repeated the identical `id` (UUID primary key) and
`created_at`/`updated_at` column definitions verbatim. Everything else
reviewed (config, database engine setup, main.py's lifespan, the four
Pydantic schemas) had no real duplication worth touching at this
codebase size — a `model_config = ConfigDict(extra="allow")` line
repeated 3 times in schemas.py was noted but judged too small (one
line) to justify a shared base class.

## Change made

Branch `refactor/d1-d2-cleanup`, commit `6c5205d` —
`app/domains/finance/models.py` only. Extracted `UUIDPrimaryKeyMixin`
and `TimestampMixin`, applied to both models. This is a standard,
idiomatic SQLAlchemy pattern, not a manufactured abstraction — and it
sets up cleanly for future models (e.g. A4's `DigestLog`) to reuse the
same mixins instead of re-copying the columns again.
